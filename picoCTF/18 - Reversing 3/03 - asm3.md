# asm3

# Descripción 
What does asm3(0xb75a8f13,0xe1860bd7,0xc8e62f81) return? Submit the flag as a hexadecimal value (starting with '0x'). 
NOTE: Your submission for this question will NOT be in the normal flag format. [Source](https://challenge-files.picoctf.net/c_fickle_tempest/a8d942aa65a7a2dbe79352e0db95f90237024106f4efd380bda7ad339151b383/test.S)
## Solución
Al aplicarle un cat al archivo fuente, podemos analizar este código
```asm
asm3:
	<+0>:	endbr32 
	<+4>:	push   ebp
	<+5>:	mov    ebp,esp
	<+7>:	xor    eax,eax
	<+9>:	mov    ah,BYTE PTR [ebp+0x9]
	<+12>:	shl    ax,0x10
	<+16>:	sub    al,BYTE PTR [ebp+0xf]
	<+19>:	add    ah,BYTE PTR [ebp+0xd]
	<+22>:	xor    ax,WORD PTR [ebp+0x12]
	<+26>:	nop
	<+27>:	pop    ebp
	<+28>:	ret    
```

Los argumentos en memoria (en orden de bytes, de izquierda a derecha) quedan así:
- arg1: ``13 8f 5a b7``
- arg2: ``d7 0b 86 e1``
- arg3: ``81 2f e6 c8``

El programa va armando el resultado en eax paso a paso:
1. eax empieza en 0
2. ``ah`` toma el byte en posición +0x9, que es el 2do byte de arg1 → ``8f``. Ahora ``ax = 8f00``
3. Shift left 16 en ax y ax solo tiene 16 bits, todo se va a ``ax = 0000``
4. ``al`` resta el byte en +0xf, que es el 4to byte de arg2, ``e1``. Entonces ``00 - e1 = 1f`` (da la vuelta). Ahora ax = ``001f``
5. ``ah`` suma el byte en +0xd, que es el 2do byte de arg2, ``0b``. Ahora ``ax = 0b1f``
6. XOR ax con los bytes en +0x12, que son el 3er y 4to byte de arg3, ``e6 c8 = c8e6`` como número. Entonces ``0b1f XOR c8e6 = c3f9``
7. Devuelve ``eax = 0x0000c3f9``

Nuestra flag entonces es:
0xc3f9
