# asm2

# Descripción 
What does asm2(0xc,0x1d) return? Submit the flag as a hexadecimal value (starting with '0x'). 
NOTE: Your submission for this question will NOT be in the normal flag format. [Source](https://challenge-files.picoctf.net/c_fickle_tempest/03ef6d65b33a69a3aee644df1385c84ab7c9e3b45d81fe05ad144e1460a9eaaf/test.S)
## Solución
Al aplicarle un cat al archivo fuente, podemos analizar este código
```asm
asm2:
	<+0>:	endbr32 
	<+4>:	push   ebp
	<+5>:	mov    ebp,esp
	<+7>:	sub    esp,0x10
	<+10>:	mov    eax,DWORD PTR [ebp+0xc]
	<+13>:	mov    DWORD PTR [ebp-0x4],eax
	<+16>:	mov    eax,DWORD PTR [ebp+0x8]
	<+19>:	mov    DWORD PTR [ebp-0x8],eax
	<+22>:	jmp    0x11d0 <asm2+35>
	<+24>:	add    DWORD PTR [ebp-0x4],0x1
	<+28>:	add    DWORD PTR [ebp-0x8],0xe4
	<+35>:	cmp    DWORD PTR [ebp-0x8],0xf5cf
	<+42>:	jle    0x11c5 <asm2+24>
	<+44>:	mov    eax,DWORD PTR [ebp-0x4]
	<+47>:	leave  
	<+48>:	ret
```

Traduciendo el código a algo entendible, notamos que el programa tiene dos variables locales y un bucle:
- var1 = segundo argumento = 0x1d (29 en decimal)
- var2 = primer argumento = 0xc (12 en decimal)

El bucle hace esto repetidamente:
- Revisa: Si var2 <= 0xf5cf, y si lo es, continúa el bucle.
- Dentro del bucle: var1 += 1 y var2 += 0xe4
- Cuando var2 supera 0xf5cf, sale y devuelve var1.

Simulando el bucle, este arranca con var1 = 0x1d, var2 = 0xc. En cada vuelta, var2 sube de 0xe4 en 0xe4 (228 decimal) hasta pasar 0xf5cf (62927 decimal):
Número de vueltas necesarias: (0xf5cf - 0xc) / 0xe4 = 62923 / 228 = 275.98... → 276 vueltas (redondeando hacia arriba). Entonces var1 = 0x1d + 276 = 29 + 276 = 305.

305 en hexadecimal = 0x131. Y esta es nuestra flag.
